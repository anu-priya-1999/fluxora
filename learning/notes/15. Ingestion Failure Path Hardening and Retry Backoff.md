# Fluxora Step 16 — Learning Notes: Ingestion Failure-Path Hardening

## 1. What Step 16 Builds

Step 16 hardens the worker ingestion pipeline against external failure modes (GitHub API errors, network degradation, rate limiting, quota exhaustion, malformed tarballs, malicious path escapes, oversized payloads, and storage blips).

It introduces a deterministic contract between error classification, repository connection status, and job queue retry policies.

---

## 2. Core Concepts

### 2.1 Permanent vs. Retryable Failures

In distributed worker pipelines, treating all failures identically leads to two major anti-patterns:
1. **The Poison Pill Loop**: Retrying permanent failures (such as missing ref, oversized repository, or revoked permissions) pointlessly hammers external APIs, consumes worker concurrency, and delays customer notification.
2. **Premature Poisoning**: Marking a repository as broken or requiring re-authentication when a transient network blip or API rate limit occurs degrades user trust.

Fluxora resolves this with explicit `IngestionError` semantics:
- `retryable: boolean`
- `repositoryStatus: RepositoryConnectionStatus | null`

### 2.2 Bounded Deterministic Exponential Backoff

When retrying transient errors, fixed intervals can cause stampeding herds against recovering third-party APIs. Fluxora uses bounded exponential backoff:
$$\text{delay} = \min(\text{baseDelay} \times 2^{\text{attemptCount} - 1}, \text{maxDelay})$$

With a 5-second base and 300-second cap:
- Attempt 1: $5 \times 2^0 = 5\text{s}$
- Attempt 2: $5 \times 2^1 = 10\text{s}$
- Attempt 3: $5 \times 2^2 = 20\text{s}$
- Attempt 4: $5 \times 2^3 = 40\text{s}$
- Attempt 5: $5 \times 2^4 = 80\text{s}$
- Attempt 6: $5 \times 2^5 = 160\text{s}$
- Attempt 7+: $\min(320, 300) = 300\text{s}$

Because attempts are stored in PostgreSQL (`jobs.attempt_count`), the backoff is completely deterministic across distributed worker nodes and worker restarts.

---

## 3. Resource Cleanup Invariant

Regardless of whether an ingestion job succeeds, fails permanently, or fails retryably, the temporary working directory allocated for extraction (`/tmp/fluxora-ingest-*`) must always be removed in a `try...catch...finally` block. This prevents disk exhaustion on worker nodes.
