# 47. Golden Fixture PR Impact Validation

## Overview & System Role

Global Step 47 is the culminating step of **Phase 6: PR Impact Analysis**. It bridges unit testing and production reliability by establishing an end-to-end, deterministic validation suite that tests the entire PR impact pipeline against a real-world repository and recorded golden Pull Request fixture with hand-verified expected impact results.

It proves that given a real PR on a real TypeScript/Next.js codebase, Fluxora's deterministic pipeline:
1. Resolves changed files to precise AST symbol seeds.
2. Performs bounded graph traversal over canonical dependency relationships.
3. Classifies direct impact (depth 1) and downstream impact (depth 2) with mathematical precision.
4. Generates immutable evidence linking every finding to exact source code provenance.
5. Persists the analysis idempotently without data corruption or tenant boundary violations.
6. Returns identical results upon re-execution.

---

## 1. Why Golden Fixtures Are Essential for Graph Digital Twins

In software dependency graph architectures:
- Synthetic mock graphs (e.g. Node A -> Node B) verify mechanical traversal logic, but fail to exercise realistic AST symbol definitions, re-exports, multi-hop module imports, route handler conventions, and schema edge cases.
- Conversely, live network-dependent CI tests against external GitHub APIs are non-deterministic, subject to rate limits, repository deletions, and external flakiness.
- **The Golden Fixture Solution**: Pinning a real-world open-source codebase (`shadcn-ui/taxonomy` at commit `298a8857c7128a0d121e7f699dfd729f23b3966d`) and recording a realistic PR with hand-verified ground truth creates a 100% deterministic, offline, CI-safe test harness that validates the actual production pipeline.

## 2. Direct Impact vs. Downstream Impact Ground Truth

A critical contribution of Step 47 is establishing unambiguous semantic precision between seed, direct impact, and downstream impact:

| Hop Level | Traversal Semantics | Taxonomy Golden PR Ground Truth | Confidence |
| --- | --- | --- | --- |
| **Depth 0 (Seed)** | AST symbol overlapping the diff hunk in `lib/subscription.ts` | `sym:lib/subscription.ts#function:getUserSubscriptionPlan:197` | $1.0$ |
| **Depth 1 (Direct Impact)** | Immediate module container and immediate importing/calling modules (`direction: "both"`) | Exactly 4 modules: `page.tsx` (billing), `posts/route.ts`, `users/stripe/route.ts`, `lib/subscription.ts` | $1.0 \times 0.9^1 = 0.90$ |
| **Depth 2 (One-Hop Downstream)** | First downstream traversal level beyond direct nodes | Exactly 45 nodes: 3 API route endpoints, 14 modules (UI components, config, libs), 28 symbols | $1.0 \times 0.9^2 = 0.81$ |

### Affected APIs
The 3 impacted API route endpoints discovered at Depth 2 are:
- `route:app/api/posts/route.ts#app-router-handler:GET:/api/posts:360`
- `route:app/api/posts/route.ts#app-router-handler:POST:/api/posts:907`
- `route:app/api/users/stripe/route.ts#app-router-handler:GET:/api/users/stripe:361`

### Unresolved Files & Negative Controls
- `content/docs/billing.mdx`: Present in the PR diff, but since Markdown docs are not part of the TypeScript AST dependency graph, it is correctly classified under `unresolvedFiles` with reason `"No matching graph nodes found in current analysis run."`, without generating synthetic phantom nodes.
- Disconnected components (e.g. `/api/og` route handler, Stripe webhook listener, site footer, site config, table of contents parser) are verified to be strictly absent from the impact sets.

## 3. Evidence Writer Provenance & Idempotency Invariants

- **Audit Provenance**: Every single direct and downstream finding ($4 + 45 = 49$) has a corresponding `impact_finding` evidence record in the `evidence` table. Each record references the exact source file path, line numbers, analysis run, and confidence.
- **Deterministic Evidence ID Generation**: Evidence IDs are derived via deterministic UUID v5 from `(analysisRunId, subjectType, subjectId, filePath, relationshipDescription)`.
- **Idempotency**: Re-running impact analysis against the same PR and analysis run updates the existing records via `ON CONFLICT (id) DO UPDATE`, creating **zero duplicate evidence records** and **zero duplicate analysis rows**.

---

## 4. Architectural Boundaries Respected

- **No Live Network**: Operates purely over local recorded files and PostgreSQL.
- **No LLM in Core**: Traversal, seed matching, and classification are 100% deterministic graph mathematics.
- **Multi-Tenant RLS**: Verified that non-member tenants cannot view, trigger, or list impact analyses or evidence across tenant boundaries.
- **Zero Phase 7 Leaks**: No clickable citation UI, AI explanations, or simulation engines were added.
