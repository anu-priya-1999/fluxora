# 24. Normalization and Barrel Resolution

## Abstract

In modern TypeScript/JavaScript codebases, barrel files (`index.ts` re-exporting modules from a directory) and re-export statements (`export { x } from "./x"`, `export * from "./y"`, `export { a as b }`) obscure the true underlying declaration site of code symbols.

Without normalization, static analysis tools create fragmented graphs where consumer imports reference intermediate barrel files rather than the canonical declarations.

Fluxora's Step 25 Normalizer solves this by deterministically resolving barrel re-export chains, deduplicating symbols, linking cross-detector entities, and producing canonical identities while preserving full provenance and cycle safety.

## Key Technical Decisions

### 1. Separation of Detection and Normalization
Detector passes (Steps 18–24) focus purely on syntactic feature extraction without cross-file mutation. The Normalizer (Step 25) ingests these isolated outputs and constructs the canonical view.

### 2. Canonical Identity Format
Symbol canonical IDs are derived strictly from their actual declaration location:
`sym:${relativePath}#${kind}:${parentName ? parentName + "." : ""}${name}:${offset}`

Re-exports do NOT create new canonical symbols; instead, re-export aliases (`exportingFile`, `exportName`, `importKind`, `location`) are recorded on the underlying canonical symbol.

### 3. Cycle-Safe Traversal
Re-export chains can form cycles (`a.ts -> b.ts -> a.ts`). The normalizer tracks visited `(file, exportName)` tuples during resolution, terminating immediately when a cycle is re-entered and marking the export resolution status as `"cyclic"`.

### 4. Ambiguous Export Handling
When multiple star re-exports (`export * from "./a"`, `export * from "./b"`) in a single barrel export conflicting symbols with the same name pointing to distinct underlying declarations, the normalizer flags the export as `"ambiguous"` and records an explicit `NormalizedUnresolvedReference`.

### 5. Immutability & Deterministic Ordering
The normalizer is a pure function. It leaves detector inputs untouched and sorts all output lists (`symbols`, `exportResolutions`, `moduleEdges`, `routes`, `events`, `databaseReferences`, `unresolved`, `diagnostics`) using alphanumeric keys to ensure identical output across runs.
