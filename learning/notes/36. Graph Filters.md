# Step 37 — Graph Filters

## 1. What Step 37 Adds
Step 37 provides graph filtering controls in the Architecture Explorer. It introduces the presentational `GraphFilters` component, typed UI filter state (`GraphFilterState`), and deterministic query mapping (`buildGraphQueryRequest`) into the existing `POST /api/v1/graph/query` pipeline.

## 2. Why Filters Belong at the Explorer/UI Boundary
Filtering controls belong as presentational UI in `GraphFilters`, state-managed inside `ArchitectureExplorerClient`. Filtering is a view parameter on how much of the deterministic digital twin the engineer wants to inspect at a time. The backend remains the source of truth for graph traversal and evidence verification.

## 3. Filter-State Data Flow
1. User adjusts a control in `GraphFilters` (node types, edge types, min confidence, max depth, or reset).
2. `GraphFilters` invokes `onChange(nextFilters)` or `onReset()`.
3. `ArchitectureExplorerClient` updates its local React `filters` state.
4. An effect triggers `buildGraphQueryRequest` and calls `fetchGraphQuery`.
5. The API server authenticates the request, executes bounded graph traversal, and returns `GraphQueryResponse`.
6. `ArchitectureExplorerClient` updates `state.graph` and reconciles `selectedNodeId` against the returned nodes.
7. `GraphCanvas`, `NodeInspectorPanel`, and `EvidenceTrail` render the synchronized filtered view.

## 4. Key Invariants & Safeguards
- **No Client Traversal Duplicate**: The client does not run BFS/DFS or graph algorithms. Filtering is expressed via the backend's `GraphQueryRequest` fields (`node_types`, `edge_types`, `min_confidence`, `max_depth`).
- **Deterministic Reset**: Clicking "Reset Filters" restores `DEFAULT_GRAPH_FILTERS` (empty node types, empty edge types, 0% confidence, max depth = 5) without affecting the repository identity, analysis run, or authentication.
- **Race Condition Prevention**: Effect-level cancellation (`isCancelled`) guarantees that older pending requests never overwrite results from newer filter actions.
- **Selection Synchronization**: When a filter removes the currently selected node from the graph, `selectedNodeId` is cleared to `null`, safely returning the `NodeInspectorPanel` to its empty state.
- **Hard Depth Limit**: Max depth is clamped in the UI to `HARD_MAX_TRAVERSAL_DEPTH` (`20`).
- **Tenancy Isolation**: The frontend never supplies `organization_id`; organization tenancy is derived on the API server.
- **No Database Imports**: `apps/web` never imports `@fluxora/db`.

## 5. Scope Boundaries
Step 37 explicitly does NOT implement:
- Step 38 Clustering & Level of Detail (LOD)
- Step 39 WebSocket live graph updates
- Step 40 Final Explorer polish
- URL search parameter state synchronization for filters
- Any third-party state manager (Zustand, Redux, Jotai)
- Simulation or change-impact analysis UI (Phase 6+)
