# 23. Tree-sitter Fallback

## Conceptual Role in Fluxora

In Phase 3 (Code Intelligence), Fluxora extracts symbols, modules, routes, events, and database references using specialized compiler-based parsers (such as the TypeScript Compiler API).

However, real-world engineering repositories contain multi-language files (JSON configuration, CSS stylesheets, HTML templates, Markdown documentation) and occasional malformed source files that the primary compiler API cannot process.

The **Tree-sitter Fallback Pass** acts as a resilient fallback parsing layer that:
1. Provides static AST parsing for non-TypeScript/JavaScript files.
2. Serves as a graceful fallback when primary compiler parsing fails.
3. Exposes generic structural units and deterministic diagnostics to later normalizers without replacing primary intelligence pipelines.

## Architectural Principles

- **Primary Pipeline Priority**: Successful primary TS/JS compilation always takes precedence. Tree-sitter is never run as a duplicate pass over valid TS/JS code.
- **Static & Isolated Analysis**: Tree-sitter runs WebAssembly grammars statically without executing code or loading target dependencies.
- **Deterministic Output**: Output identifiers, diagnostics, and structural units follow strict deterministic sorting and line/column range conventions.
