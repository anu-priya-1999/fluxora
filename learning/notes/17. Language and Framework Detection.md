# Fluxora Step 18 — Learning Notes: Language and Framework Detection

## 1. Role in Code Intelligence Pipeline

Language and framework detection (`docs/architecture/05-component-responsibilities.md §5.2`) is the gateway step of Phase 3 (Code Intelligence).

Before Fluxora can extract AST symbols or trace import dependencies, it must classify the target repository's technology stack to determine:
- Which parser pipelines to activate (e.g., TypeScript Compiler API vs. fallback tree-sitter grammars).
- Which framework-specific pattern matchers to run (e.g., Next.js App Router rules).
- Which files to skip (caches, build artifacts, lockfiles).

---

## 2. Determinism and the AI Edge

A central design pillar of Fluxora is:
> **Deterministic core, probabilistic edge.**

Stack detection does not involve an LLM or probabilistic model:
1. File extensions (`.ts`, `.tsx`, `.js`, `.mjs`, etc.) and configuration files (`package.json`, `tsconfig.json`) are unambiguous facts.
2. An LLM prompt asking *"What framework is this repository?"* would introduce non-determinism, API failure modes, latency, and hallucination risks into a foundational analysis step.
3. Every test run and analysis run over the same snapshot SHA produces bit-identical detection results.

---

## 3. Sandboxing & Safe Evaluation

Customer repositories contain **untrusted code**.

The detector:
- Only reads file names, directory structures, and manifest text contents.
- Never imports `.js` or `.ts` files into the Node.js runtime.
- Never executes build scripts, config evaluation (`eval`), or package manager commands (`npm install`).
- Rejects directory traversal escapes when reading file contents.

---

## 4. Normalization and False Positive Prevention

### Extension Normalization
Different modern ECMAScript / TypeScript extensions are mapped to canonical languages:
- `.ts`, `.mts`, `.cts`, `.tsx` $\to$ `TypeScript`
- `.js`, `.mjs`, `.cjs`, `.jsx` $\to$ `JavaScript`
- `.md`, `.markdown`, `.mdx` $\to$ `Markdown`

### Evidence-Backed Framework Detection
Frameworks are identified only when concrete structural or manifest evidence exists:
- `Next.js` requires the `next` dependency and/or `next.config.*` + Next.js router directory layout.
- `React` requires the `react` / `react-dom` dependencies or JSX/TSX source components in a recognized React/Next.js stack.
- Arbitrary file names containing substring matches (such as `next-auth.ts` or `docs/react.md`) do not trigger false-positive framework detections.
