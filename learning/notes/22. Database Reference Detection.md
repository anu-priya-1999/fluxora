# 22. Database Reference Detection

Static AST-based database reference detection allows Fluxora to map code intelligence to underlying data structures deterministically without runtime execution or live database access.

## Supported Ecosystems & Operations

1. **Prisma**:
   - `prisma.<model>.findMany / findUnique / findFirst / create / createMany / update / updateMany / delete / deleteMany / upsert`
   - `$queryRaw`, `$executeRaw`, `$transaction`
2. **Drizzle ORM**:
   - `select().from(table)`, `insert(table)`, `update(table)`, `delete(table)`, `db.query.<table>.findMany / findFirst`
3. **TypeORM**:
   - `getRepository(Entity).find / save / insert / update / delete`
   - `userRepo.find / save`, `manager.find(Entity, ...)`
4. **Sequelize**:
   - `User.findAll / findOne / findByPk / create / bulkCreate / update / destroy / upsert`

## Provenance Rules

Calls are only classified as database references if the receiver or function has established ORM provenance in the file scope (imports from `@prisma/client`, `drizzle-orm`, `typeorm`, `sequelize`, or explicit model/repository constructors).

Arbitrary object method calls such as `foo.findMany()`, `file.save()`, `element.create()`, or `user.update()` without ORM provenance are rejected as false positives.

## Dynamic Resource Resolution

Statically knowable model/table names are extracted as `resourceName` with `status: "resolved"`. Dynamic or computed expressions (e.g. `prisma[dynamicModel].findMany()`) resolve to `resourceName: null` with `status: "unresolved"`.
