# 51. Analysis Coverage View

## Overview & System Role

Global Step 51 implements the **Analysis Coverage View**, concluding **Phase 7: Evidence Engine** of the Fluxora Engineering Roadmap (`docs/architecture/17-implementation-roadmap.md`, Phase 7, Step 4).

Step 51 directly addresses the foundational trust question of the Fluxora digital twin:
> **"How much of the analyzed surface has verified evidence, and where are the gaps?"**

In Fluxora, an AI or static analysis system must never present an illusion of total omniscience. If a repository has 873 analyzed relationships and 31 lack verified evidence (e.g. unverified dynamic invocations or heuristic hypotheses), the system must explicitly surface that 96.5% of the system is evidence-backed, while pointing engineers directly to the 31 missing-evidence items so gaps can be audited or refined.

---

## 1. Architectural Philosophy: The Three Core Metrics

Phase 7 establishes three distinct, orthogonal dimensions for every conclusion in Fluxora:

| Dimension | Question Answered | Metric / Representation | Governed Invariant |
| --- | --- | --- | --- |
| **Provenance (Step 48 & 49)** | *"Why does Fluxora believe this conclusion?"* | `EvidenceRecord` (file path, line range, AST symbol) | Evidence Completeness Invariant (`pnpm lint:evidence`) |
| **Confidence (Step 50)** | *"How strong or certain is this conclusion?"* | Numeric score $0.0 \dots 1.0$, visual weighting (stroke width, dashed) | Principle P3: Uncertainty is presented, never smoothed over |
| **Coverage (Step 51)** | *"How much of the analyzed scope has evidence?"* | Ratio: $\frac{\text{Evidence-Backed Conclusions}}{\text{Analyzed Conclusions}}$ | Principle P2: Claims are grounded in verifiable code evidence |

### Never Substitute Confidence for Coverage
- **High confidence + evidence** = Covered, high-certainty conclusion.
- **Low confidence + evidence** = Covered, low-certainty conclusion (e.g., deep 4-hop impact finding with traversal decay, backed by AST call chains).
- **No evidence** = **Uncovered** (regardless of confidence).

## 2. Key Engineering Pillars

### A. Strictly Scoped Denominators (No Mixed Metrics)
Coverage is always strictly scoped to an authoritative snapshot or analysis run. Denominators from different analysis surfaces are **never** combined into a synthetic repository-wide average:
1. **Graph Edge Surface**:
   - Scope: Loaded analysis run (`analysisRunId`).
   - Denominator: Total graph edges in the slice (`edges.length`).
   - Numerator: Graph edges with `typeof edge.evidence_id === "string" && edge.evidence_id.length > 0`.
   - Categories: Grouped by edge type (`IMPORTS`, `CALLS`, `EXPOSES_ROUTE`, `QUERIES_DB`, etc.).
2. **PR Impact Finding Surface**:
   - Scope: PR Impact Analysis (`impactAnalysisId`, `pullRequestId`).
   - Denominator: Total impact findings across all categories (`direct`, `downstream`, `api`, `event`, `service`).
   - Numerator: Impact findings with `evidence_ids.length > 0 || evidence_id != null`.
   - Categories: 5 authoritative impact tiers.
   - Unresolved Files: Surfaced as non-code / unmapped files in the PR (`unresolved_files`).

### B. Actionable Gap Remediation
The primary UX value of Step 51 is making missing evidence actionable:
- The user expands the coverage drawer and selects the **"Missing Evidence"** filter.
- Each uncovered edge or finding renders with an **"Inspect in Graph"** action.
- Clicking the action highlights the edge or node in `GraphCanvas` and opens the inspection panel in `NodeInspectorPanel`, displaying its metadata and honest "Missing Evidence" alert.

### C. Multi-Channel Accessibility (WCAG 2.1 AA)
- Visual progress bars use semantic HTML and ARIA attributes:
  `role="progressbar"`, `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`.
- Textual figures and counts accompany every progress indicator (e.g. `Covered: 842 | Missing: 31 | Total: 873`, `96.5%`).
- Color is never the sole indicator of health; distinct badges, icons, and text labels ensure complete comprehension in grayscale or for colorblind users.

### D. Zero Backend Mutation & Pure Presentation Engine
- No direct database connections from the browser.
- No client-side re-execution of graph queries or AST parsers.
- All metrics are calculated deterministically in memory from the authoritative read-only API responses already delivered to the Explorer.

## 3. UI Integration Summary

1. **AnalysisCoverageBar (`apps/web/src/components/graph/AnalysisCoverageBar.tsx`)**:
   - Integrated directly into the Architecture Explorer between the header/ChangeModeBar and GraphFilters.
   - Compact summary bar showing status dot, scope pill, counts, percentage badge, visual progress bar, and expand toggle.
   - Surface selector tabs (`Graph Edges` vs. `PR Impact Findings`) when PR Change Mode is active.
2. **Expanded Category & Findings Drawer**:
   - Category Breakdown grid with individual mini progress bars and covered/total ratios.
   - Unresolved files notice for unmapped PR diffs.
   - Interactive findings list with `All`, `Covered`, and `Missing Evidence` filter pills.
   - Direct graph selection triggers (`onSelectEdge`, `onSelectNode`).
3. **NodeInspectorPanel Integration**:
   - Edge inspection displays an explicit `Covered` vs `Missing Evidence` status chip next to the edge type.
