# 38. Graph Clustering and Level-of-Detail (LOD)

## What is Level-of-Detail (LOD)?

Level-of-Detail (LOD) is a technique borrowed from 3D computer graphics and mapping software (like Google Maps). When you look at the entire world map, you don't see street names or house numbers—you see continents, countries, and major cities. As you zoom in, highways appear, then local streets, and finally building outlines.

In software architecture visualization, the exact same principle applies. A codebase might have 5,000 functions, 300 modules, 10 microservices, and 4 databases. If you render all 5,000 functions on screen at once when zoomed out:
1. It looks like a tangled mess of illegible text and overlapping boxes (the classic "hairball" problem).
2. The browser's DOM / SVG engine slows down to a crawl because it has to manage thousands of nodes and bezier edge calculations.
3. The engineer cannot easily understand the high-level architecture.

LOD solves this by tying visual density to the user's viewport zoom level.

---

## The Three Tiers of LOD in Fluxora

Fluxora defines three deterministic tiers based on the React Flow viewport zoom level:

1. **Overview Tier (`zoom < 0.6`)**:
   - **What's visible:** Only high-level architectural constructs: `application`, `service`, `database`, `package`.
   - **What's hidden:** Detailed code-level nodes (`module`, `api`, `event`, `symbol`).
   - **Use case:** Big-picture architectural understanding, boundaries, system topology.

2. **Module Tier (`0.6 <= zoom < 1.1`)**:
   - **What's visible:** Packages, modules, APIs, events, services, and databases.
   - **What's hidden:** Fine-grained code symbols (`symbol`).
   - **Use case:** Understanding communication routes, API boundaries, and module import graphs.

3. **Detail Tier (`zoom >= 1.1`)**:
   - **What's visible:** Everything, including individual function declarations, methods, and classes (`symbol`).
   - **Use case:** Deep dive into specific implementation routines, method calls, and AST-level relationships.

## Key Invariants & Principles

### 1. Pure Presentation Layer
LOD is purely a projection mechanism. It does not alter the backend graph truth or perform graph traversals in the browser. The backend remains the sole authoritative source of truth.

### 2. Selected Node Immunity
What happens if an engineer selects a fine-grained function node in the Node Inspector, and then zooms out to see the whole system?
If the node were hidden, the selection would break and the Inspector would clear unexpectedly.
**Invariant:** If a node is selected (`selectedNodeId`), it is **always visible**, regardless of the current LOD tier. This guarantees continuous inspection and prevents jarring UI state losses.

### 3. No Dangling Edges
If node A connects to node B, and node B is hidden because it's a symbol, what happens to the edge?
**Rule:** An edge is rendered if and only if **both** source and target nodes are currently visible. No orphaned or dangling edges are ever sent to React Flow.

### 4. Debounced Viewport Updates
Recalculating the graph on every single animation frame of a zoom wheel (`onMove`) causes unnecessary rerenders. By reacting on `onMoveEnd`, the UI updates smoothly once the zoom gesture settles.
