# 30. Bounded-Depth Recursive-CTE Graph Traversal — Scoped Traversal, Cycle Prevention, and Evidence Preservation

## Context & Engineering Objective

Global Step 30 introduces `traverseGraph` in `@fluxora/db`, implementing **Bounded-Depth Recursive-CTE Graph Traversal** over PostgreSQL (`docs/architecture/05-component-responsibilities.md §5.9`, `docs/architecture/06-database-schema.md §6.1`, `docs/architecture/17-implementation-roadmap.md §Phase 4 Step 4`).

This utility enables downstream services (Impact Analysis Engine, Simulation Engine, BFF query endpoints) to execute deterministic graph reachability queries over the `graph_nodes` and `graph_edges` PostgreSQL tables.

---

## Core Technical Concepts Explained

### 1. What a Graph Traversal Does
Graph traversal starts at a given node (the root or starting point) and explores connected edges to discover reachable downstream or upstream nodes. In software system digital twins, graph traversal determines which modules, services, APIs, or events are affected when a specific symbol or component changes.

### 2. What a Recursive CTE Is
A Common Table Expression (CTE) defined with `WITH RECURSIVE` allows a SQL query to reference its own output recursively. It consists of:
- **Anchor Query**: Executes once to establish the initial result set (depth 0, starting node).
- **Recursive Query**: Executes repeatedly against the output of the preceding iteration to discover next-hop neighbors.
- **Termination**: Recursion stops when the recursive term returns zero rows or hits a stopping predicate (`WHERE depth < maxDepth`).

### 3. Maximum Depth Enforcement
Server-side validation enforces `0 <= maxDepth <= 20` (`HARD_MAX_TRAVERSAL_DEPTH`). In SQL, the recursive clause checks `WHERE t.depth < maxDepth`, halting expansion at the configured hop count.

### 4. Cycle & Multi-Path Handling
- **Cycle Prevention**: Each row tracks visited node IDs in a path array (`ARRAY[n.id::text]`). The recursive term specifies `WHERE NOT (next_node.id::text = ANY(t.path))`, pruning cyclic branches.
- **Deduplication**: When multiple paths reach the same node (fan-in), `ROW_NUMBER() OVER (PARTITION BY node_id ORDER BY depth ASC, path::text ASC) WHERE rn = 1` selects the shortest path and minimum depth deterministically.

### 5. Multi-Tenancy & RLS Isolation
All traversal queries execute within `withTenant(pool, organizationId, ...)` which sets `app.current_org_id`. Both the anchor query and recursive join enforce `analysis_run_id = $2::uuid`, preventing cross-tenant or cross-run data leakage.

### 6. Evidence Preservation
If `includeEvidence: true`, `traverseGraph` fetches corresponding `evidence` records for all returned nodes and edges directly from PostgreSQL, maintaining strict provenance.
