# Note 28: Evidence Writer and CI Evidence Lint — First-Class Provenance and Architectural Enforcement

## Plain English Summary

In code intelligence platforms, asserting a structural relationship (for example, "File A imports File B" or "API Route /users queries Postgres") is only half the battle. If a user cannot inspect *why* the system made that claim down to the exact line of code, the system becomes a black box that engineers cannot trust.

Fluxora's core invariant requires every graph node and edge to be accompanied by concrete, un-fabricated **Evidence**.

Prior to Step 29, graph persistence code generated evidence records inline using ad-hoc string formatting. Step 29 introduces a dedicated **Evidence Writer** abstraction that makes evidence persistence an explicit architectural requirement. Additionally, a static **CI Evidence Lint** check verifies that no developer can add or modify graph-writing code without routing through `EvidenceWriter`.

---

## Technical Deep-Dive

### 1. Evidence Writer Architecture (`EvidenceWriter`)

The `EvidenceWriter` sits between code-intelligence projections and PostgreSQL persistence:

1. **Deterministic Identity Generation**:
   Evidence primary keys are derived deterministically using SHA-256:
   `ID = SHA256(analysisRunId + ":evidence:" + subjectType + ":" + subjectId + ":" + filePath + ":" + relationshipDescription)`
   This guarantees that re-running graph construction on the same repository snapshot produces identical UUID primary keys.

2. **Provenance Preservation & Non-Fabrication**:
   Evidence records capture:
   - `analysisRunId`: Analysis execution scope
   - `subjectType`: `"graph_node"` | `"graph_edge"` | `"impact_finding"` | `"simulation_state"`
   - `subjectId`: UUID of the associated node or edge
   - `filePath`: Relative source file path
   - `symbolId`: Optional canonical symbol ID
   - `lineStart` / `lineEnd` / `columnStart` / `columnEnd`: 1-based source location coordinates
   - `relationshipDescription`: Human-readable explanation
   - `confidence`: Numeric score between 0.0 and 1.0
   - `metadata`: Key-value contextual attributes

   When source coordinates or symbol IDs are absent (e.g. unresolved imports or file-level references), `EvidenceWriter` explicitly stores `null` rather than fabricating dummy values.

3. **Transactional & Idempotent Persistence**:
   Evidence is persisted alongside nodes and edges within a single PostgreSQL transaction (`withTenant`).
   Database writes use `ON CONFLICT (id) DO UPDATE`, guaranteeing idempotency and preventing duplicate rows on repeated executions.

### 2. Static Architectural CI Evidence Lint

To ensure long-term codebase maintainability, Step 29 introduces a static AST checker built with the TypeScript Compiler API (`ts.createSourceFile`):

- **No Live Database Required**: Analyzes source code files directly without needing PostgreSQL or background services.
- **Narrow Architectural Enforcement**: Inspects functions performing graph node or edge creation/persistence (`INSERT INTO graph_nodes`, `INSERT INTO graph_edges`, `nodeMap.set`, `createGraphNode`, `createGraphEdge`, `persistGraphBuild`, `buildGraphProjection`).
- **AST Compliance Check**: Asserts that every graph-write path explicitly invokes `EvidenceWriter`. If a function creates graph records without calling `EvidenceWriter`, the linter fails with line numbers and remediation instructions.
- **CI Gate**: Integrated into `.github/workflows/ci.yml` via `pnpm lint:evidence`.

---

## Key Takeaways for Senior Engineering Interviews

- **Evidence as a First-Class Concern**: Graph relationships are worthless without verifiable provenance. Elevating Evidence to a dedicated layer ensures evidence cannot be forgotten or bypassed.
- **Deterministic Primary Keys over Random UUIDs**: Deriving evidence IDs from semantic seeds preserves idempotency across repeated pipeline runs without needing complex database cleanups.
- **Static Architectural Linting over Runtime Checks**: Catching unevidenced write paths in CI via AST analysis prevents architectural erosion before code ever reaches production.
