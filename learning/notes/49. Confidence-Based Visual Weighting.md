# 50. Confidence-Based Visual Weighting

## Overview & System Role

Global Step 50 implements **Confidence-Based Visual Weighting** under **Phase 7: Evidence Engine** of the Fluxora Engineering Roadmap (`docs/architecture/17-implementation-roadmap.md`, Phase 7, Step 3).

In Fluxora, confidence is not a subjective metric or an afterthought; it is a **first-class presentation signal** governed by Architecture Principle P3:
> **Principle P3 — Uncertainty is presented, never smoothed over.** Every inferred relationship carries a confidence score; low-confidence edges are rendered distinctly (dashed, muted) rather than treated as facts or hidden. When the system doesn't know, it says so.

Step 50 takes the authoritative confidence values calculated by Fluxora's backend analysis and traversal decay engine and maps them into clear, monotonic, accessible visual encodings across the graph canvas, blast-radius finding drawer, evidence citations, and inspector panels.

---

## 1. Architectural Philosophy: Evidence vs. Confidence

A critical architectural distinction in Fluxora is the separation of **Evidence** from **Confidence**:

| Dimension | Evidence (Step 48 & 49) | Confidence (Step 50) |
| --- | --- | --- |
| **Definition** | Concrete source code provenance (file, line range, AST symbol). | A numeric probability score (`0.0` to `1.0`) measuring relationship certainty or traversal strength. |
| **Role** | Answers: *"Why does Fluxora believe this relationship exists?"* | Answers: *"How strong or direct is this relationship?"* |
| **Persistence** | Immutable records stored in PostgreSQL via `EvidenceWriter`. | Numeric column on `GraphEdge`, `GraphNode`, and `ImpactFinding`. |
| **UI Presentation** | Clickable `EvidenceCitation` navigating to GitHub permalinks. | Visual prominence (stroke width, stroke dash, opacity, tier chips). |
| **Failure Mode** | Missing evidence = unverified claim (forbidden in production). | Low confidence = heuristic or deep hop; rendered distinctly, never hidden. |

## 2. Key Engineering Pillars

### A. Presentation-Only Normalization (Zero Browser Recomputation)
- The backend/API is strictly authoritative.
- The browser **never** computes traversal decay formulas (such as `0.9 ** depth`).
- Normalization module `confidence-data.ts` maps numeric values deterministically to presentation tiers:
  - **High (≥ 90%)**: Direct AST imports, 1-hop impact. Solid, thick stroke (2.0px), 100% opacity.
  - **Medium (70%–89%)**: Dynamic imports, 2–3 hops impact. Solid, standard stroke (1.5px), 85% opacity.
  - **Low (< 70%)**: Heuristic/naming links, 4+ hops impact. Distinct dashed stroke (`4 4`, 1.25px), 65% opacity.

### B. Missing-Confidence Discipline (Non-Fabrication)
- If confidence is missing (`undefined`, `null`, or `NaN`), `normalizeConfidence` returns `null`.
- The system renders neutral default styling without fabricating synthetic percentages or default bands.
- We never invent placeholder values like `100%` or `0%` when metadata is absent.

### C. Multi-Channel Accessibility (WCAG 2.1 AA)
- Confidence is never communicated through color or opacity alone.
- Edges vary in **stroke width**, **dash pattern** (solid vs. dashed), **opacity**, and provide detailed screen-reader announcements via `aria-label`:
  `"CALLS edge from auth-service to db, High confidence, 95 percent"`.
- Finding cards in the PR Change Mode drawer and citation chips in the inspector display explicit text percentages and tier labels (`High`, `Medium`, `Low`).

### D. Absolute Selection Priority
- When an engineer selects an edge or node, user intent takes absolute precedence over change-mode and confidence weighting.
- Selected edges immediately highlight with prominent `#3b82f6` (blue), `strokeWidth: 3px`, and `opacity: 1.0`, ensuring clear visual focus.

## 3. UI Integration Surfaces

1. **GraphCanvas & React Flow Edge Layer**:
   - `mapDomainGraphToFlow` computes SVG styles via `computeEdgeConfidenceStyles`.
   - High-confidence edges appear prominent and solid; low-confidence edges appear dashed and slightly muted.
   - Low-confidence edges remain fully interactive, clickable, and selectable.
2. **Change Mode Findings Drawer (`ChangeModeBar.tsx`)**:
   - Findings across direct, downstream, API, event, and service categories display confidence chips with tier styling.
   - Low-confidence finding cards receive distinct dashed borders (`border-dashed border-amber-300`).
   - The visual legend includes clear guides for both high-confidence and low-confidence edge encodings.
3. **EvidenceCitation & EvidenceCitationList**:
   - Compact chips display `data-confidence-tier` and `aria-label`.
   - Expanded cards display `Confidence: 92% (High confidence)`.
   - When confidence is absent, confidence indicators are omitted cleanly.
4. **NodeInspectorPanel**:
   - Edge inspection displays formatted confidence percentages, accessible labels, and tier badges.
   - Node impact findings display hop distance and decayed impact confidence with visual alerts for low-confidence findings.
