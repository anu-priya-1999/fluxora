# Fluxora Step 21 — Learning Notes: Next.js API Route & Express Router Detection

## 1. Role in Code Intelligence Pipeline

API route and router detection (`docs/architecture/05-component-responsibilities.md §5.5`, `docs/architecture/17-implementation-roadmap.md §Phase 3 Step 4`) is the fourth milestone of Phase 3 (Code Intelligence).

While Step 20 answered:
> *"How are repository modules connected through imports and exports?"*

Step 21 answers:
> *"Which files and functions represent HTTP API routes or Express routers?"*

It connects raw source code symbols and files to architectural interface concepts (HTTP endpoints, request handlers, routers).

---

## 2. Invariant: Deterministic Static Analysis vs. Runtime Execution

Customer repository code is untrusted:
- **Never Execute Handlers**: Handlers and routers are never invoked, loaded into the Node.js runtime, or executed.
- **Pure AST & Path Classification**: Next.js route handlers are classified by repository-relative file paths (`app/**/route.ts`, `pages/api/**`) combined with exported AST symbols (`GET`, `POST`, default export).
- **Express Provenance Tracking**: Variables named `app` or `router` are only classified when their provenance is proven via import/require analysis of `"express"`.
- **Reproducible Findings**: Given the same snapshot files, output route lists, router definitions, and IDs are identical.

---

## 3. Next.js Routing Conventions

### App Router Route Handlers
- Files: `app/**/route.(ts|tsx|js|jsx)` or `src/app/**/route.(ts|tsx|js|jsx)`
- Handlers: Named exports matching HTTP methods (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`)
- Route Path: Derived by stripping `route.(ts|tsx|js|jsx)` and prepending `/`.
- Example: `app/api/posts/[id]/route.ts` -> `/api/posts/[id]`.

### Pages Router API Routes
- Files: `pages/api/**` or `src/pages/api/**`
- Handlers: Default export (`export default function handler() {}` or `export default handler;`)
- Route Path: Derived by taking the subpath under `pages/api/` (stripping trailing `/index` or standalone `index`).
- Example: `pages/api/users.ts` -> `/api/users`.

---

## 4. Express Router Detection & False-Positive Prevention

In JavaScript/TypeScript codebases, variables named `app` and `router` are ubiquitous across non-Express libraries (e.g. custom routing tables, micro-frameworks, CLI tools).

To eliminate false positives:
1. **Module Import Requirement**: The file must explicitly import `express` or require `"express"`.
2. **Factory Invocation Provenance**:
   - `const app = express()` binds `app` as an Express application.
   - `const router = express.Router()` or `const router = Router()` binds `router` as an Express router.
3. **Registration Extraction**:
   - `router.get(path, handler)` -> records HTTP method `GET` and path.
   - `router.use(path, childRouter)` -> records middleware/router mount relationship.
4. **Static Path Extraction**:
   - String literals and simple template literals are extracted.
   - Non-literal expressions (e.g. `BASE + "/users"`) fall back safely to `(unresolved)`. Code is never evaluated.
