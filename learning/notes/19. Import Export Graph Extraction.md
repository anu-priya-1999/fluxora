# Fluxora Step 20 — Learning Notes: Import/Export Graph Extraction

## 1. Role in Code Intelligence Pipeline

Import/export graph extraction (`docs/architecture/05-component-responsibilities.md §5.3`, `docs/architecture/17-implementation-roadmap.md §Phase 3 Step 3`) is the third milestone of Phase 3 (Code Intelligence).

While Step 19 answered:
> *"What symbols exist inside each file?"*

Step 20 answers:
> *"How are repository modules connected through imports and exports?"*

It discovers the topology of repository modules, serving as the bridge between per-file AST parsing and whole-system architectural graphs.

---

## 2. Invariant: Deterministic Static Analysis vs. Execution

Customer code is untrusted input:
- **Never Execute**: Code is never executed, evaluated (`eval`), dynamically imported via Node.js runtime, or passed to package managers (`npm install`, `pnpm install`).
- **In-Memory Resolution**: All path alias lookups and relative traversals operate strictly against an immutable in-memory map of snapshot files.
- **Reproducible Topology**: Given the same snapshot files and `tsconfig.json`, the generated edges, IDs, and resolution statuses are identical.

---

## 3. Handling Path Aliases and tsconfig.json

Modern TypeScript repositories extensively use path aliases:
```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```
Step 20 harnesses the TypeScript Compiler API's configuration parser (`ts.readConfigFile`, `ts.parseJsonConfigFileContent`) and module resolver (`ts.resolveModuleName`) wrapped with a virtual `ts.ModuleResolutionHost`. This faithfully mimics TypeScript compiler behavior without disk access.

---

## 4. Re-Exports and Barrel Files

A common architectural trap is premature barrel normalization:
- If `src/index.ts` re-exports `src/services/payment.ts`, Step 20 records an explicit `re_export` edge from `src/index.ts` to `src/services/payment.ts`.
- It does **not** collapse `src/app.ts -> src/index.ts` into `src/app.ts -> src/services/payment.ts`.
- Preserving explicit barrel edges maintains true file dependencies. Normalization and barrel collapsing is strictly reserved for Step 25.

---

## 5. Distinction Between Resolution Statuses

Imports fall into four distinct categories:
1. `internal`: Resolves to a recognized repository source file in the snapshot.
2. `external`: Third-party packages (e.g. `react`, `next/link`).
3. `unresolved`: Relative imports or matched alias paths pointing to non-existent files in the repository.
4. `unsupported_dynamic`: Dynamic imports or requires with non-string-literal expressions.
