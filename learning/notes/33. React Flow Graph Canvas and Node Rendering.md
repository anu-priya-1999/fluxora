# 34. React Flow Graph Canvas and Node Rendering

## 1. Overview & Context

In Step 34, Fluxora transitions from the deterministic backend graph construction layer (Phase 4) into the interactive visual architecture UI (Phase 5). Step 34 provides the core diagramming canvas and per-node-type renderer using `@xyflow/react` (React Flow).

---

## 2. Why React Flow?

React Flow is chosen for Fluxora's Architecture Explorer for several structural reasons:
1. **Custom Node Types**: First-class support for completely custom React components as nodes via `nodeTypes`.
2. **Handle Architecture**: Flexible placement of `source` and `target` handles matching directional dependency flow (top-to-bottom or left-to-right).
3. **Built-in Pan, Zoom, and Minimap**: Native support for interactive viewport navigation without reinvention.
4. **Performance & Virtualization**: Only nodes in the visible viewport (or within active render thresholds) undergo heavy DOM rendering.
5. **Decoupled State**: Allows external state managers (Zustand / local props) to feed nodes and edges directly without managing an internal imperative canvas loop.

---

## 3. Component Responsibilities

### `GraphCanvas.tsx`
- Acts as the client-side boundary wrapper around `<ReactFlow />`.
- Accepts pure arrays of `nodes` and `edges` (domain `GraphNode` or API `GraphQueryResponseNode`).
- Calls `mapDomainGraphToFlow` deterministically inside `useMemo`.
- Configures controls (`Controls`), background (`Background`), and selection callbacks (`onNodeClick`).
- Does **not** perform network requests or trigger API queries.

### `NodeRenderer.tsx`
- Presentational custom node component.
- Uses `getNodeVisualConfig` from `node-styles.ts` to assign colors, badges, and labels.
- Renders:
  - Header with node type label (`Application`, `Service`, `Module`, `Symbol`, `API Route`, etc.) and optional depth.
  - Node name.
  - File path or canonical ID in monospace.
  - Confidence percentage (when `< 1.0`).
  - Selected highlight border and shadow.
  - Incoming (`target`) handle at the top, outgoing (`source`) handle at the bottom.

### `graph-mapping.ts`
- Translates Fluxora domain/API objects into React Flow `Node` and `Edge` structures.
- Generates a deterministic grid layout without random offsets.
- Discards dangling edges where source or target node is missing.
- Free from side-effects or network access.

---

## 4. Scope Discipline: What Step 34 Does NOT Implement

To ensure strict architectural phase boundaries:
- **No Explorer Route**: `/repositories/[repoId]/explorer` is deferred to Step 35.
- **No API Fetching**: Neither `POST /api/v1/graph/query` nor TanStack Query is imported or invoked.
- **No WebSockets**: Live event invalidation is not wired up.
- **No NodeInspectorPanel or EvidenceTrail**: Side inspection panels belong to Step 36.
- **No GraphFilters**: Filtering UI belongs to Step 37.
- **No Clustering / LOD**: Graph pre-aggregation belongs to Step 38.
- **No Impact / Simulation Overlays**: Deferred to Phase 6 and Phase 8.

---

## 5. Performance Limitations at this Stage

1. **Initial Grid Layout**: The initial layout is a straightforward deterministic grid. Advanced layout engines (e.g. Dagre, Elk, or Web Worker layout computations) will be layered in subsequent steps.
2. **Graph Size**: Without server-side clustering or LOD (Step 38), rendering graphs with thousands of nodes directly in the browser would degrade frame rates. This is by design: large graphs are intended to be queried with bounded depth (`max_depth`) or cluster parameters.
