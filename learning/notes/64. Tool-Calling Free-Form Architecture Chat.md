# 64. Tool-Calling Free-Form Architecture Chat

## Key Takeaways

1. **Controlled Tool Surface (`query_graph`, `get_evidence`, `run_simulation`)**:
   - Instead of giving the LLM generic file-reading or SQL access, Fluxora exposes only three schema-validated tools backed by its deterministic graph traversal, evidence repository, and simulation engine.
   - `query_graph` and `get_evidence` are strictly read-only; `run_simulation` is the sole bounded, non-destructive state-creating operation (creating synthetic `Scenario` and `Simulation` records via the deterministic simulation engine, not unrestricted database mutation or autonomous remediation). The model cannot modify source code, repositories, existing graph records, infrastructure, or existing simulations.
   - Tenant (`organizationId`), `repositoryId`, and `analysisRunId` are always injected from authenticated server context (`TrustedChatContext`)—never accepted from model arguments.
2. **Provider-Neutral Gateway Extension**:
   - `ModelGateway` now supports `ToolDefinition`, `ModelToolUseBlock`, and `ModelToolResultBlock` without leaking `@anthropic-ai/sdk` types into the chat orchestrator.
   - `MockModelProvider` can queue `toolUses` responses so the entire multi-round tool loop runs deterministically in CI without API keys.
3. **Accumulated Manifest Grounding & Provenance Limits**:
   - As tools execute, returned evidence IDs are accumulated into `allowedEvidenceIds`.
   - The final response must pass `chat-query-output-v1` validation and cite only IDs in that manifest (atomic whole-response rejection on fabricated IDs).
   - Manifest membership proves citation provenance, not automatic semantic entailment.
4. **Bounded Loops & Prompt-Injection Defense**:
   - Hard caps (`MAX_TOOL_ROUNDS = 5`, `MAX_TOTAL_TOOL_CALLS = 10`, `MAX_SIMULATIONS_PER_REQUEST = 2`, `MAX_EXECUTION_TIME_MS = 45_000`) prevent runaway loops and cost blowups.
   - Untrusted user/history text is XML-delimited and unicode-escaped (`\u003c`, `\u003e`, `\u0026`).
