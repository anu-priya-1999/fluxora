# 67. Runtime Telemetry Data Foundation

## What Was Built
- **Migration `0029_runtime_telemetry_storage.sql`**: Added `public.telemetry_sources` and `public.observations` with `FORCE ROW LEVEL SECURITY`, composite foreign keys, triggers, and query indexes.
- **Shared Contracts (`@fluxora/shared-types`)**: Added `TelemetryProvider`, `TelemetrySourceStatus`, `TELEMETRY_SOURCE_STATUS_TRANSITIONS`, `TelemetrySource`, and `Observation`.
- **Persistence Layer (`@fluxora/db`)**: Added `createTelemetrySource`, `getTelemetrySourceById`, `listTelemetrySources`, `updateTelemetrySource`, `appendObservation`, and `queryObservations`.

## Key Engineering Decisions
1. **Opaque Encrypted Envelope Contract**: Rather than storing plaintext JSON or inventing custom cryptography, `connection_config` enforces `^(enc|kms):v[0-9]+:[^\s]+$` at both TypeScript and PostgreSQL `CHECK` boundaries until KMS envelope encryption is added to `packages/infrastructure`.
2. **Composite FK `(repository_id, node_id)` with `ON DELETE SET NULL (node_id)`**: Guarantees an observation can never link a source in Repo A to a `GraphNode` in Repo B or another tenant, while allowing unmapped observations (`node_id IS NULL`) and preserving historical observations if a `GraphNode` is pruned.
3. **PostgreSQL `NUMERIC` & UTC `timestamptz`**: Preserves exact decimal metric precision (returned as canonical decimal strings) and original observation timestamps distinct from `created_at`.
