# Fluxora Step 19 — Learning Notes: Per-File Symbol Extraction

## 1. Role in Code Intelligence Pipeline

Per-file symbol extraction (`docs/architecture/05-component-responsibilities.md §5.3`, `docs/architecture/17-implementation-roadmap.md §Phase 3 Step 2`) is the second milestone of Phase 3 (Code Intelligence).

Following language and framework detection (Step 18), symbol extraction transforms raw source code files into a structured, queryable catalog of in-file code entities.

---

## 2. Invariant: Deterministic Analysis vs. Execution

A foundational rule in Fluxora is:
> **Customer repository code is untrusted input.**

1. **Static AST Analysis**: Symbols are extracted strictly by parsing source text into Abstract Syntax Trees using the TypeScript Compiler API (`ts.createSourceFile`).
2. **Never Execute**: Code is never evaluated (`eval`), dynamically imported (`import(filePath)`), or executed via subprocesses. Doing so could expose the analysis runner to arbitrary code execution, security exploits, or infinite loops.
3. **Pure & Reproducible**: Given identical file content, the extractor produces bit-identical symbols and offsets.

---

## 3. Distinction Between Step 19 and Step 20

- **Step 19 (Per-file symbol extraction)**:
  - Answers: *"What symbols exist in this isolated source file?"*
  - Scope: Functions, classes, methods, interfaces, types, enums, variables, constants, and immediate export markings.
  - Zero cross-file awareness.

- **Step 20 (Import/export graph extraction)**:
  - Answers: *"How do files connect to one another?"*
  - Scope: Import statements, module specifiers, barrel re-exports, `tsconfig.json` path alias resolution, and directed dependency edges across files.

Keeping Step 19 strictly file-local ensures high parallelism, simple cache invalidation, and complete testability without mock file systems.

---

## 4. Error Handling and Syntax Fault Tolerance

Real codebases often contain syntax errors, draft edits, or incomplete syntax:
- `ts.createSourceFile` is inherently fault-tolerant and generates partial ASTs even in the presence of syntax errors.
- Parse diagnostics are harvested into structured `RepositorySymbolDiagnostic` records rather than crashing the worker.
- Valid symbols outside the erroneous construct are safely preserved.
