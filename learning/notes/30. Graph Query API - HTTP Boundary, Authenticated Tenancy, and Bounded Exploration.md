# 31. Graph Query API — HTTP Boundary, Authenticated Tenancy, and Bounded Exploration

## Context & Engineering Objective

Global Step 31 implements `POST /api/v1/graph/query` in `apps/api` (`docs/architecture/07-api-architecture.md §7.2`, `docs/architecture/17-implementation-roadmap.md §Phase 4 Step 5`).

This endpoint acts as the public HTTP interface for the internal recursive-CTE graph traversal primitive built in Step 30 (`traverseGraph`). It connects authenticated web and API consumers to Fluxora's deterministic software twin graph.

---

## Core Technical Concepts Explained

### 1. API Boundary vs. Internal Query Layer
The internal query layer (`traverseGraph` in `@fluxora/db`) executes SQL recursive CTEs directly against PostgreSQL with tenant isolation (`withTenant`). It requires low-level database connection pools, internal domain types, and specific SQL parameters.
The API boundary (`handleGraphQuery` in `apps/api`) translates external HTTP protocol concerns (headers, authentication tokens, Content-Type, JSON parsing, error shapes) into clean query options, and projects raw database entities into public API structures.

### 2. Request Validation & Defensive Parsing
External HTTP requests are untrusted input. The request parser (`parseGraphQueryBody`):
- Verifies UUID formats for `analysis_run_id` and `start_node_id`.
- Rejects client-supplied `organization_id` to strictly prevent tenant impersonation.
- Enforces direction enum limits (`"downstream"`, `"upstream"`, `"both"`).
- Restricts traversal depth between `0` and `20` (`HARD_MAX_TRAVERSAL_DEPTH`).
- Rejects non-finite or out-of-range confidence thresholds (`0 <= min_confidence <= 1`).
- Validates edge and node types against shared domain enums.

### 3. Authenticated Tenant Derivation
Tenant isolation is non-negotiable. Fluxora never trusts `organization_id` sent in the request body. Instead:
1. The client presents a Bearer JWT session token.
2. The server authenticates the token via Clerk and retrieves the user's connected GitHub identity.
3. The server resolves or provisions the tenant user in PostgreSQL.
4. The authenticated user's `organizationId` is passed into `withTenant` to enforce Row-Level Security (RLS).

### 4. Public-to-Internal Concept Mapping
Public API consumers use intuitive directional vocabulary:
- `"downstream"`: Explore outgoing dependencies (calls, emitted events, database queries). Mapped to internal `"outgoing"`.
- `"upstream"`: Explore incoming dependencies (callers, event subscribers). Mapped to internal `"incoming"`.
- `"both"`: Explore both directions. Mapped to internal `"both"`.

### 5. Deterministic Confidence Filtering
When clients request `min_confidence`:
- Any node with `confidence < min_confidence` is pruned from the returned set.
- Any edge with `confidence < min_confidence` or that connects to a pruned node is removed.
- Evidence records belonging to removed nodes or edges are excluded.
This ensures the client receives a coherent sub-graph where all edges connect existing nodes.

### 6. Read-Only Query Semantics
Graph querying is strictly read-only. It performs zero mutations against `graph_nodes`, `graph_edges`, or `evidence`. No AI or LLM components are involved.
