# 35. Architecture Explorer Route and Graph API Fetching

## 1. What is the Architecture Explorer Route?

The Architecture Explorer route (`/repositories/[repoId]/explorer`) is the primary user-facing visualization surface in Fluxora. It allows engineers to inspect their repository's deterministic software digital twin.

In Global Step 35, the route wires the Next.js frontend to the backend graph query engine. It receives route parameters identifying the repository and query parameters identifying the analysis run and entry node, performs authenticated HTTP requests against `POST /api/v1/graph/query`, transforms the returned domain graph into React Flow primitives, and mounts the Step 34 `GraphCanvas`.

---

## 2. Why Does the Route Exist Separately from GraphCanvas?

`GraphCanvas` (Step 34) is strictly a presentational component:
- It knows how to render nodes and edges in React Flow.
- It provides viewport controls, zooming, panning, and styling.
- It contains **zero** network logic, authentication knowledge, or URL routing dependencies.

The Explorer Route (`page.tsx` + `explorer-client.tsx`):
- Owns URL routing (`/repositories/[repoId]/explorer`), Next.js App Router metadata, and server-side Clerk authentication.
- Coordinates HTTP data fetching against `POST /api/v1/graph/query`.
- Handles page-level lifecycle states (loading, empty / analysis-not-ready, network/auth errors).
- Passes pure data into `GraphCanvas`.

This separation ensures testability, prevents UI components from coupling to backend transports, and guarantees that `GraphCanvas` can be reused in future steps (e.g., simulation mode, PR change review) without changing its core rendering mechanics.

---

## 3. Server vs. Client Boundary

- **`page.tsx` (Server Component)**:
  - Validates user authentication via Clerk's server-side `auth()`.
  - Redirects unauthenticated users to `/sign-in`.
  - Validates repository and analysis context from route params and query parameters.
  - If analysis parameters are missing, immediately renders an accessible "Graph Analysis Not Ready" empty state without invoking client bundles.
  - Reads the configured API URL (`readFluxoraApiUrl()`) and renders the client boundary.

- **`explorer-client.tsx` (Client Component)**:
  - Marked `"use client"`.
  - Obtains the session token via Clerk's `useAuth().getToken()`.
  - Executes `fetchGraphQuery(...)`.
  - Translates `GraphQueryResponse` to React Flow nodes/edges via `transformGraphResponseToFlow(...)`.
  - Renders the interactive `GraphCanvas`.

---

## 4. How Repository → Analysis Run → Graph Query Works

1. **Route Request**:
   The user navigates to `/repositories/<repoId>/explorer?analysis_run_id=<runId>&start_node_id=<nodeId>`.
2. **Context Resolution**:
   The route validates `repoId`, `analysis_run_id` (or alias `run_id`), and `start_node_id` (or alias `node_id`) against UUID regex. If either identifier is missing or malformed, the page renders a deterministic empty state explaining that graph analysis is not ready.
3. **Graph API Request**:
   The client issues `POST /api/v1/graph/query` with body:
   ```json
   {
     "analysis_run_id": "<uuid>",
     "start_node_id": "<uuid>",
     "direction": "both"
   }
   ```
4. **Backend Traversal**:
   The API server verifies the Clerk Bearer token, extracts the tenant's `organization_id`, and executes the bounded recursive CTE traversal (Step 30).
5. **Transformation & Rendering**:
   The client receives `GraphQueryResponse` and passes it through `mapDomainGraphToFlow(...)` to generate layout coordinates and typed node data for `GraphCanvas`.

---

## 5. Security & Tenancy Invariant

- The frontend never specifies or invents `organization_id`.
- Tenant boundaries are strictly enforced in the backend via PostgreSQL Row-Level Security (RLS) and verified session tokens.
- `apps/web` does **not** import `@fluxora/db` or connect directly to PostgreSQL.
