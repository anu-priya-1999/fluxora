## 2. Key Architecture Questions & Answers

### Q: What is a golden fixture repository and why does Fluxora need one?
**A:** A golden fixture is a real-world open-source codebase recorded at a specific immutable commit used as a ground-truth reference for deterministic testing. Fluxora needs it because upcoming code intelligence steps (framework detection, symbol extraction, import graph construction, route detection, and graph normalization) require realistic application complexities (path aliases, barrel files, server components, and ORM models) that cannot be adequately covered by synthetic unit tests alone. Testing against a recorded fixture guarantees reproducibility and eliminates GitHub network dependencies or rate limits.

### Q: Which repository was chosen and what makes it suitable?
**A:** `shadcn-ui/taxonomy` (`https://github.com/shadcn-ui/taxonomy`). It is a full-stack Next.js and TypeScript application featuring:
- App Router (`app/(auth)`, `app/(dashboard)`, `app/api`)
- Server and Client Components
- Path aliases configured in `tsconfig.json` (`@/*`)
- Prisma ORM schema and migrations (`prisma/schema.prisma`)
- NextAuth and Stripe integrations
- A moderate size (177 files, ~2.16 MB total on disk) that exercises comprehensive analysis without bloating repository storage or test runtimes.

### Q: Why pin to a 40-character Git commit SHA rather than a branch?
**A:** Branch names (like `main` or `master`) and tags are mutable references that can advance, be rebased, or be deleted upstream. A 40-character commit SHA uniquely identifies an immutable Git tree object. Pinning to `298a8857c7128a0d121e7f699dfd729f23b3966d` ensures that every test run on every machine evaluates the exact same bytes every time.

### Q: Does this repository restrict what repositories Fluxora will support?
**A:** No. Fluxora is designed to ingest and model any arbitrary GitHub repository connected by customers. The golden fixture is solely an internal development and testing asset to ensure parsing accuracy and regression safety across Phase 3 and Phase 4.

### Q: What does Step 17 deliberately NOT implement?
**A:** Step 17 does not implement AST parsing, ts-morph / TypeScript Compiler API symbol extraction, route detection, graph database persistence, or AI summaries. It strictly establishes the fixture data, metadata contracts, and fixture integrity tests.
