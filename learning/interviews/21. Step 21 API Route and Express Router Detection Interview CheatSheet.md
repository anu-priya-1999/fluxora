# Step 21: Next.js API Route & Express Router Detection Interview CheatSheet

## High-Level Pitch
Step 21 implements deterministic static detection for Next.js API route handlers and Express routers. It transforms code intelligence from *"what files and symbols exist"* (Steps 19 & 20) into *"what HTTP APIs and network endpoints does this codebase expose?"*. It operates purely through AST and path pattern matching without ever executing customer code, maintaining strict tenant boundaries and reproducible results.

---

## Key Architectural Concepts

### 1. Next.js App Router vs. Pages Router API Conventions
- **App Router (`app/**/route.ts`)**:
  - Route handlers are declared via file naming convention.
  - HTTP methods correspond to named exports: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`.
  - Frontend pages (`app/**/page.tsx`) must never be classified as API routes.
  - Public route path is derived by stripping the `route.(ts|tsx|js|jsx)` suffix.
- **Pages Router (`pages/api/**`)**:
  - Any supported source file under `pages/api/` is an API route.
  - Handlers are represented by a single default export (`export default function handler(req, res)`).
  - Public route path is derived from the subpath under `pages/api/` (with special handling for `index`).

### 2. Express Provenance Tracking & False-Positive Prevention
- **The Problem**: Variables named `app` or `router` appear everywhere (state managers, CLI routers, testing harnesses, plain objects).
- **The Solution**: Multi-pass AST scope analysis:
  1. Prove origin: Must have `import express from "express"`, `import { Router } from "express"`, or `require("express")`.
  2. Prove instantiation: Must be initialized via `express()`, `express.Router()`, or `Router()`.
  3. Extract registrations: Only inspect `.get()`, `.post()`, `.use()` calls on verified variable identifiers.
  4. Plain objects like `const router = { get() {} }` are never classified as Express routers.

### 3. Static Path Extraction vs. Dynamic Expressions
- String literals (`"/users"`) and simple non-substituted template literals (`` `/users` ``) are extracted statically.
- Computed expressions (e.g. `BASE_PATH + "/users"`, `config.apiPrefix`) are never dynamically evaluated with `eval()` or runtime execution. They fall back safely to `"(unresolved)"`.

### 4. Security & Untrusted Input Guarantee
- Repository source code is untrusted.
- Handlers are never executed or imported into Node.js.
- AST parsing is done via `ts.createSourceFile` with in-memory text buffers.

## Common Interview Questions & Answers

### Q: Why not just use regex on the file contents to detect `router.get`?
**A:** Regex cannot verify provenance or context. It would match comments, string literals in logs, documentation strings, and unrelated objects named `router`. Using the TypeScript Compiler API AST allows scoping to confirmed variable declarations and exact call expression semantics with precise 1-based line/column source locations.

### Q: How does Step 21 relate to Step 18, 19, and 20?
**A:**
- **Step 18** determines if Next.js or Node.js exists at the repository level.
- **Step 19** extracts raw symbols (functions, classes, exports) in individual files.
- **Step 20** links files through imports/exports and path-alias resolution.
- **Step 21** identifies the external API boundary (routes & routers) by pairing AST symbol knowledge with framework-specific routing conventions.

### Q: Why aren't you writing these routes to the PostgreSQL database now?
**A:** Fluxora separates extraction from graph persistence. Phase 3 is purely code intelligence extraction producing typed in-memory contracts. Phase 4 will persist normalized nodes (`GraphNode`), edges (`GraphEdge`), and evidence (`Evidence`) transactionally in PostgreSQL.
