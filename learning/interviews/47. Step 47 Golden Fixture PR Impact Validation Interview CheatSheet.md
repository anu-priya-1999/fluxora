# Step 47: Golden Fixture PR Impact Validation Interview CheatSheet

## Core Narrative & Problem Statement

**Q: Why is golden-fixture validation required if we already have unit tests for the impact engine and persistence?**
- **Unit vs. Integration Gap**: Unit tests verify isolated algorithmic units against synthetic mocks. However, real-world AST symbol extraction, TypeScript module re-exports, multi-hop imports, framework route conventions, and database transactions can exhibit emergent behaviors that synthetic mocks fail to capture.
- **Hand-Verified Ground Truth**: Golden-fixture validation executes the entire pipeline (diff parsing -> symbol resolution -> bounded graph traversal -> persistence -> evidence linking -> API retrieval) against a real codebase (`shadcn-ui/taxonomy`) and asserts that the actual output matches an explicit, hand-verified expected manifest down to the exact canonical IDs.

## Technical Highlights

### 1. Direct Impact vs. Downstream Impact Definition
- **Question**: "How do you distinguish between direct impact and downstream impact in a software digital twin?"
- **Answer**:
  - **Seed (Depth 0)**: The specific AST symbol or declaration directly modified by the PR diff hunks (e.g., `sym:lib/subscription.ts#function:getUserSubscriptionPlan:197`).
  - **Direct Impact (Depth 1)**: The immediate enclosing module container and the first-degree consumers that import or directly call the seed symbol (e.g. 4 modules: `page.tsx`, `posts/route.ts`, `users/stripe/route.ts`, `lib/subscription.ts`). Confidence = $1.0 \times 0.9^1 = 0.90$.
  - **One-Hop Downstream (Depth 2)**: The downstream consumers and descendants of the depth 1 nodes (e.g. 45 nodes: 3 API routes, 14 modules, 28 symbols). Confidence = $1.0 \times 0.9^2 = 0.81$.
  - We never assert vague array lengths or overall affected lists; we assert exact set equality on sorted canonical IDs.

### 2. Handling Unresolved & Non-Code Files
- **Question**: "How does the pipeline handle non-code files like Markdown or documentation modified in a PR?"
- **Answer**: "Non-code files (e.g. `content/docs/billing.mdx`) are tracked in the PR changed files list. During symbol resolution, if no AST symbols or graph nodes correspond to the path, the file is classified under `unresolvedFiles` with reason `'No matching graph nodes found in current analysis run.'`. The engine NEVER invents synthetic phantom nodes for unmapped files."

### 3. Evidence Writer Auditability & Idempotency
- **Question**: "How does Fluxora guarantee audit provenance and prevent duplicate records during automated CI runs?"
- **Answer**: "Every finding is linked to an `impact_finding` evidence record generated by `EvidenceWriter`. Evidence IDs are generated via deterministic UUID v5 from `(analysisRunId, subjectType, subjectId, filePath, relationshipDescription)`. When the analysis is re-run with the same ID or across retries, PostgreSQL executes `ON CONFLICT (id) DO UPDATE`, updating the finding evidence in-place without generating duplicate evidence rows."
