# 34. Step 34 React Flow Graph Canvas Interview CheatSheet

## Core Architectural Concepts

### Q1: Why should data fetching NOT live inside `GraphCanvas`?
**Answer**:
`GraphCanvas` is a presentational visualization component. Coupling data fetching to the canvas would:
1. Violate Single Responsibility: mixing HTTP fetching, cache management, and canvas rendering.
2. Prevent reuse: making it impossible to render mock fixture data in tests or reuse the canvas across PR impact views, scenario simulations, or embedded widgets.
3. Obscure state ownership: page/route containers (and React Query in Step 35) should own query parameters, caching, and network error boundaries.

### Q2: Why is deterministic node and edge identity critical when integrating React Flow?
**Answer**:
If the frontend generated random UUIDs or used timestamps (`Date.now()`) for React Flow node/edge IDs:
1. Re-rendering or receiving incremental updates would cause React Flow to unmount and remount every node, losing pan/zoom position, node selection, and dragging state.
2. Deep links (e.g. `/explorer/[nodeId]`) would break because render IDs would not match domain `canonical_id` or database `id`.
3. Diffing between previous and updated graphs (Step 32 events) would be impossible to visualize smoothly without stable keys.

### Q3: How do we prevent the frontend from becoming a "second graph builder"?
**Answer**:
The Fluxora frontend adheres strictly to Invariant 4.1: *The frontend must never invent graph relationships or become a second graph-building system.*
All nodes, edges, edge directions, and confidence scores originate from backend static analysis stored in PostgreSQL under EvidenceWriter provenance. The frontend mapping layer (`mapDomainGraphToFlow`) only formats coordinates and visual styles; it never infers implicit dependencies or synthesizes fake edges.

### Q4: Why is `"use client"` necessary for `GraphCanvas` in Next.js App Router?
**Answer**:
React Flow relies directly on client-side browser primitives:
- DOM bounding box measurements (`getBoundingClientRect`) to position handles and calculate viewport bounds.
- Mouse and touch event listeners for zooming, panning, and dragging.
- Browser Canvas and SVG contexts.
These capabilities cannot be evaluated on the server during SSR. Hence, `GraphCanvas` is marked as a client component while parent pages can remain server components that stream initial shell markup.

### Q5: How is multi-node-type extensibility handled without code bloat?
**Answer**:
Using the `node-styles.ts` registry and a single unified `NodeRenderer` with configuration dispatch. Rather than maintaining 8 duplicate JSX component files with duplicated handle logic and selection styling, `NodeRenderer` delegates visual token resolution (`borderColor`, `badgeBg`, `label`, `category`) to `getNodeVisualConfig`, ensuring consistent behavior while keeping custom styling easily extensible for future overlay modes (change-mode, simulation-mode).
