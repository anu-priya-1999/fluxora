# Step 23 — Database Reference Detection Interview CheatSheet

## High-Level Pitch

"Step 23 implements static, AST-based database reference detection across four core ORM ecosystems: Prisma, Drizzle, TypeORM, and Sequelize. It extracts database interaction points, operations, and model/table names deterministically, without ever executing repository code or connecting to a database."

## Architectural Questions & Answers

### Q1: Why static analysis instead of connecting to a real database or executing ORM code?
**A:** Fluxora enforces strict security and determinism invariants. Repository code is untrusted input. Executing customer code, importing ORM modules, or opening database connections in worker environments introduces arbitrary code execution, secret leakage, and environment dependencies. Static AST analysis over TypeScript Compiler API is 100% side-effect free, deterministic, and sandboxed.

### Q2: How do you prevent false positives on generic methods like `.findMany()`, `.save()`, or `.create()`?
**A:** We construct an in-file `DatabaseProvenanceScope`. A call is only classified if its receiver or function is proven to originate from a supported ORM import (`@prisma/client`, `drizzle-orm`, `typeorm`, `sequelize`), a known constructor (`new PrismaClient()`, `drizzle()`), or a recognized model class (`extends Model`, `@Entity()`). Arbitrary objects calling `.save()` or `.create()` are rejected.

### Q3: How do you handle dynamic table or model names?
**A:** When a table/model argument is dynamic (e.g. `prisma[dynamicModel].findMany()`), we do not guess or use heuristics. The detector safely outputs `status: "unresolved"` and `resourceName: null`, preserving accurate evidence for downstream graph processing without introducing hallucinated dependencies.

### Q4: How is the operation taxonomy designed?
**A:** ORM-specific methods map cleanly into eight canonical operations: `read`, `insert`, `update`, `delete`, `upsert`, `query`, `execute`, and `transaction`. This normalizes disparate ORM APIs into a unified language for dependency graph construction in later phases.
