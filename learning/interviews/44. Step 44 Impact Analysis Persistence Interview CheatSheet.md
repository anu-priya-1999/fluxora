# Step 44: Impact Analysis Persistence Interview CheatSheet

## Core Narrative & Problem Statement

**Q: Why separate the impact analysis engine (Step 43) from impact persistence (Step 44)?**
- **Separation of Concerns**: Calculating a blast radius is a pure algorithmic traversal problem (diff parsing, symbol mapping, graph BFS, confidence decay, cycle termination). Persisting it is an infrastructure concern (database migrations, transactions, Row-Level Security, JSONB serialization, idempotency).
- **Testability**: The engine can be tested in-memory against hundreds of synthetic graphs in milliseconds without waiting on database roundtrips. The persistence layer can focus on atomicity, RLS boundaries, and evidence linking.

## Technical Highlights

### 1. The Evidence Invariant (Principle P2 & P4)
- **Question**: "How do you prove an impact analysis finding is accurate?"
- **Answer**: "Every finding stored in `impact_analyses` creates a corresponding `impact_finding` record in the `evidence` table via `EvidenceWriter`. The evidence record stores the exact source file path, line numbers, hop depth, and traversal path. Findings in the stored record reference these evidence IDs. If evidence generation fails, the transaction rolls back."

### 2. Idempotency & Deterministic Primary Keys
- **Question**: "What happens if a background worker restarts mid-analysis or the same PR webhook is delivered twice?"
- **Answer**: "Evidence IDs are derived deterministically using SHA-256 over semantic properties: `analysisRunId`, `subjectType`, `subjectId`, `filePath`, and `relationshipDescription`. Re-running persistence produces the exact same UUIDs. Database inserts use PostgreSQL `ON CONFLICT (id) DO UPDATE`, guaranteeing idempotency and preventing duplicate rows."

### 3. Multi-Tenancy & Defense-in-Depth
- **Question**: "How do you ensure customer A cannot see customer B's PR impact reports?"
- **Answer**: "PostgreSQL Row-Level Security (RLS) is enabled with `FORCE ROW LEVEL SECURITY`. Every connection is initialized using `withTenant` which sets `app.current_org_id`. Policies on `impact_analyses` verify that the referenced `pull_request_id` belongs to the authenticated tenant via `fluxora_pull_request_in_current_tenant()`. Attempting a cross-tenant read returns 0 rows at the engine level."
