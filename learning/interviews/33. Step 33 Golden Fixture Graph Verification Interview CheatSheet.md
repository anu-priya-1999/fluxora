# Step 33 Golden Fixture Graph Verification Interview CheatSheet

## Executive Summary & Quick Answers

- **What is Global Step 33?**
  Step 33 is the end-to-end integration and verification gate for Fluxora's graph pipeline. It takes an actual multi-file TypeScript codebase (`taxonomy`), runs it through normalized AST extraction, builds the relational graph, persists it into PostgreSQL, reads it back via production repositories, and verifies strict canonical contracts on nodes, edges, evidence, determinism, and multi-tenant RLS isolation.

- **Why is an end-to-end golden fixture test necessary if unit tests already exist?**
  Unit tests isolate individual modules with synthetic inputs. A golden fixture test verifies that all components—AST parsers, normalization algorithms, relational schema constraints, `EvidenceWriter` triggers, and transactional outbox events—work together cohesively on realistic code without data distortion or schema violations.

- **What are the canonical node ID formats verified in Step 33?**
  - **Modules**: `mod:<filepath>` (e.g., `mod:lib/db.ts`)
  - **Symbols**: `sym:<filepath>#<symbolName>:<lineStart>` (e.g., `sym:lib/db.ts#db:5`)
  - **API Routes**: `route:<filepath>#<handler>:<method>:<path>:<lineStart>` (e.g., `route:app/api/posts/route.ts#app-router-handler:GET:/api/posts:360`)

- **What evidence invariants are enforced during persistence?**
  Every node and edge must have a corresponding evidence record in the `evidence` table, capturing the exact file path, positive 1-based start line/column coordinates, a non-empty relationship description, and confidence score. This guarantees that every node and edge in the digital twin is traceable to physical source code.

- **How is tenant isolation proven in Step 33?**
  The test sets `FLUXORA_DATABASE_ROLE = "fluxora_rls_test"` and opens a transaction via `withTenant` for Tenant B (`orgB`). Queries to `listGraphNodes` and `listGraphEdges` return zero records from Tenant A's graph, proving PostgreSQL Row-Level Security (RLS) is strictly enforced.

## In-Depth Interview Questions & Answers

### 1. What edge-case bugs were discovered during Step 33 end-to-end verification?
**Answer:**
Two important edge cases were discovered and resolved:
1. **Multi-line Coordinate AST Constraint**:
   In multi-line TypeScript declarations, the start column on line $N$ can exceed the end column on line $N+k$ (e.g., line 5 col 25 to line 8 col 10). The previous constraint checked `column_end >= column_start` unconditionally. We refined the validation in `EvidenceWriter` and database migration `0015` so that `column_end >= column_start` is only enforced when `line_start == line_end`.
2. **PostgreSQL NOTIFY 8000-Byte Payload Limit**:
   PostgreSQL's `pg_notify` channel limits payloads to 8000 bytes. When diffing the large golden graph (490 nodes, 888 edges), the initial serialized `graph.updated` event exceeded this threshold. Migration `0016` updated `fluxora_notify_event()` to send a summary notification if `octet_length > 7500`, while the full payload remains durably stored in the `events` table.

### 2. How does Step 33 ensure determinism and idempotency?
**Answer:**
- **Determinism**: Re-running the pipeline on identical fixture files produces byte-for-byte identical node IDs, edge triples, and evidence attachments.
- **Idempotency**: Re-running graph persistence against the same repository snapshot executes without creating duplicate records or causing constraint conflicts.

### 3. What is the boundary of Step 33 relative to Phase 5?
**Answer:**
- **Step 33 (Phase 4)**: Verifies backend relational data structures, graph topology, evidence links, and PostgreSQL persistence.
- **Phase 5**: Implements the interactive React Flow visual explorer, web UI canvas, edge rendering, layout engines, and user-facing graph navigation. Step 33 touches zero UI or React code.

### 4. How does the Step 30 CTE traversal perform on the golden graph?
**Answer:**
Step 33 Contract 7 executes `traverseGraph` starting from an API route module (`app/api/posts/route.ts`). It traverses both downstream dependencies (imported libraries like `lib/db.ts` and `lib/auth.ts`) and upstream API route endpoints, confirming that the recursive SQL query correctly traverses the persisted graph structure within bounded depth without cycles.
