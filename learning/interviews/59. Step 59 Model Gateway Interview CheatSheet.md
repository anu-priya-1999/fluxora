# Step 59: Model Gateway Foundation — Interview CheatSheet

## Role Context
Staff / Principal AI Infrastructure and Distributed Systems Engineer building Fluxora — an AI-powered software digital twin providing deterministic dependency mapping, blast-radius calculation, and grounded failure explanations.

---

## 1. High-Level Concept & Gateway Architecture

### Q: Why build a custom Model Gateway rather than calling the Anthropic or OpenAI SDK directly in application workers?
**Answer:**
Direct SDK calls scattered across application workers introduce severe architectural debt:
1. **Coupling to Provider Types**: Upgrading SDK versions or swapping models leaks breaking changes across business logic.
2. **Inconsistent Resilience**: Each developer implements ad-hoc retries (or forgets them), risking infinite retry loops or fragile error handling.
3. **Uncontrolled Costs**: Without centralized usage instrumentation, token spend is invisible until the monthly cloud bill arrives.
4. **Secret Leaks in Logs**: Raw error payloads frequently dump request headers and authentication tokens into log aggregators.
5. **Broken Offline Workflows**: Developers and CI pipelines require live API credentials even for non-AI tasks like AST parsing or UI tests.

The **Model Gateway** establishes a single controlled boundary that abstracts providers behind a normalized contract (`ModelGatewayRequest` $\to$ `ModelGatewayResponse`), encapsulates retries, timeouts, and fallback routing, tracks microdollar token costs, and provides an offline deterministic mock for local development and CI.

## 2. Resilience, Retries, and Fallback Routing

### Q: How do you decide which errors are retryable versus fatal in the Model Gateway?
**Answer:**
We classify errors strictly based on idempotency and failure semantics:
- **Retryable (Transient Infrastructure / Capacity Failures)**:
  - `429 RateLimitError`: The client exceeded a concurrency or token quota. Bounded exponential backoff or respecting the provider's `Retry-After` header allows recovery.
  - `5xx InternalServerError / Bad Gateway`: Temporary provider outages or server hiccups.
  - `408 / ETIMEDOUT Connection Timeouts`: Network-level packet drops or temporary endpoint unresponsiveness.
- **Fatal (Permanent Client / Configuration Errors)**:
  - `401 Unauthorized / 403 Forbidden`: Invalid or revoked API key. Retrying will never succeed and burns rate limits. Fail closed immediately.
  - `400 Bad Request / 422 Unprocessable Entity`: Schema or prompt payload violation.
  - `Caller Cancellation (AbortSignal)`: The caller no longer wants the response. Any further retry or fallback is wasted work and cost.

### Q: What is the fallback policy, and why do we not retry fallback models indefinitely?
**Answer:**
The fallback policy operates as a two-tier strategy:
1. Attempt the configured primary model (`claude-sonnet-5-5`).
2. Retry eligible transient failures up to `maxPrimaryRetries` (default: 2 retries, 3 total attempts) with exponential backoff.
3. If primary retries are exhausted, try the configured secondary model (`claude-haiku-5-5`) **exactly once**, subject to its own task timeout.
4. If the fallback model succeeds, return the normalized response with `usedFallback: true`.
5. If the fallback model fails, throw a typed `ModelGatewayError.retriesExhausted`, preserving the primary error in `error.primaryError` for diagnostic auditability.

We limit fallback to a single attempt because if both the primary and secondary models are failing, the issue is almost certainly a catastrophic provider-wide outage or account-level quota exhaustion. Retrying endlessly adds latency without increasing success probability.

## 3. Cost Accounting & Pricing Registry

### Q: How does Fluxora accurately track LLM token spend across multi-attempt requests?
**Answer:**
We implement an injectable `ModelPricingRegistry` keyed by model identifier:
- Rates are defined separately for input tokens and output tokens per million tokens:
  $$\text{cost\_usd} = \left(\frac{\text{input\_tokens}}{1{,}000{,}000} \times \text{rate}_{\text{in}}\right) + \left(\frac{\text{output\_tokens}}{1{,}000{,}000} \times \text{rate}_{\text{out}}\right)$$
- **Aggregate Request Accounting**: In a scenario where Attempt 1 (Sonnet) reports billable tokens before encountering an error, and Attempt 2 (Haiku fallback) succeeds, the gateway computes the total cost across all billed attempts.
- **Honest Representation of Missing Data**: If a model is not registered in the pricing table, or if token counts are null (as in mock mode), the gateway returns `costUsd: null` rather than fabricating zero cost. Zero cost is a dangerous lie in billing analytics.
- **Precision**: Results are rounded to 6 decimal places (microdollars) to eliminate IEEE 754 floating-point inaccuracies.

## 4. Cancellation & Timeout Propagation

### Q: What happens when a user navigates away or cancels a long-running AI explanation request?
**Answer:**
The gateway listens to the request's `AbortSignal`:
1. **Pre-dispatch**: If already aborted, the request is rejected immediately with `ModelGatewayError.aborted()` without touching the provider adapter.
2. **In-Flight API Call**: The provider adapter forwards the `AbortSignal` to the Anthropic client's request options. When the caller aborts, the HTTP socket is terminated immediately, preventing the provider from generating tokens that won't be used.
3. **Retry Sleep Loop**: If the request is aborted during an exponential backoff sleep delay, the sleep timer is cleared immediately via `clearTimeout`, and the promise rejects without waiting out the remaining backoff duration.

## 5. Secret Safety & Redaction

### Q: How do you prevent customer repository code or Anthropic API keys from appearing in OpenTelemetry logs or traces?
**Answer:**
We employ a defense-in-depth sanitization model:
1. **Automated Error Redaction**: All error messages pass through `sanitizeErrorMessage()`, which matches regex patterns for Anthropic keys (`sk-ant-[a-zA-Z0-9_-]+`) and Bearer tokens, replacing them with `[REDACTED_API_KEY]`.
2. **Low-Cardinality Telemetry**: OpenTelemetry metric attributes and log events only record low-cardinality metadata (`provider`, `model`, `task_type`, `prompt_version`, `outcome`, `error_category`, `is_mock`).
3. **Strict Logging Invariant**: Prompts, customer repository files, diffs, and raw message payloads are **strictly forbidden** from log attributes and span tags. Only latency, token counts, and sanitized error categories are emitted.

## 6. Architecture Boundaries: Deterministic Core vs. Probabilistic AI Edge

### Q: What is the difference between Model Gateway fallback and Product Deterministic Fallback?
**Answer:**
- **Model Gateway Fallback (Phase 9 Step 1 / Step 59)**:
  - Operates inside the AI infrastructure layer.
  - Switches from a primary LLM (`claude-sonnet-5-5`) to a secondary LLM (`claude-haiku-5-5`) when transient errors exhaust primary retries.
  - Returns an AI-generated explanation.
- **Product Deterministic Fallback (Phase 9 Step 8 / Step 66 - ADR-010)**:
  - Operates at the product orchestration layer.
  - If the Model Gateway fails entirely OR if the LLM's response fails schema or evidence-grounding validation after retries, Fluxora generates a **non-AI, template-based explanation** directly from the deterministic graph nodes and evidence rows.
  - Guarantees that product availability and blast-radius visibility never depend on a third-party AI provider's uptime.
