# Step 38: Graph Clustering and Level-of-Detail Interview CheatSheet

## High-Level Pitch
"In Step 38, we implemented client-side Level-of-Detail (LOD) for Fluxora's Architecture Explorer. As codebase graphs grow to thousands of nodes, displaying symbols, modules, and services simultaneously causes canvas clutter and browser performance degradation. We implemented a deterministic 3-tier LOD strategy tied to React Flow's viewport zoom: low zoom highlights architectural services/databases, medium zoom shows modules and APIs, and high zoom reveals granular AST symbols. The system guarantees zero dangling edges, preserves selected nodes regardless of zoom, and operates purely in the presentation layer without altering backend graph truth."

---

## Likely Interview Questions & Concise Answers

### Q1: Why implement Level-of-Detail on the client rather than having the backend filter the query?
**Answer:**
Zooming and panning are continuous, high-frequency user interactions (60fps gestures). Making network round-trips to the backend database on every zoom change introduces latency, spinner flickers, and server load. By querying the bounded graph context once via `POST /api/v1/graph/query` (with Step 37 filters applied), the client can perform sub-millisecond, deterministic visual LOD filtering entirely in memory.

### Q2: How do you prevent React Flow from breaking when nodes are hidden by LOD?
**Answer:**
If an edge references a hidden node, React Flow will either log console warnings or render broken connector lines pointing to `(0, 0)`. We solve this deterministically in `computeLodGraph`: we collect `visibleNodeIds` first, and only include an edge if `visibleNodeIds.has(edge.source) && visibleNodeIds.has(edge.target)`.

### Q3: What happens if a user selects a detailed symbol node and then zooms all the way out?
**Answer:**
We implemented **Selected Node Immunity**:
```typescript
if (options.selectedNodeId && node.id === options.selectedNodeId) {
  return true;
}
```
Even if a node is a fine-grained symbol that would ordinarily be hidden in the `overview` tier, if it is the currently selected node, it remains visible. This preserves the `NodeInspectorPanel` and `EvidenceTrail` without jumping or clearing the user's active context.

### Q4: How do you avoid performance issues while the user is actively zooming?
**Answer:**
Instead of recomputing the visible set on every frame of a trackpad pinch or mouse wheel (`onMove`), we listen to `onMoveEnd`. This natural debouncing ensures recomputations only happen when the gesture stabilizes. Furthermore, `computeLodGraph` is a pure function wrapped in `useMemo`, ensuring identity stability across unrelated rerenders.

### Q5: Did you implement synthetic clustering or node-type LOD? Why?
**Answer:**
We used deterministic node-type and depth-based LOD rather than fabricating synthetic cluster containers. Creating artificial clusters from string heuristics (like path segment splitting) risks creating misleading architectural abstractions and breaking the 1:1 invariant with real `EvidenceRecord`s. Our approach preserves exact domain IDs and ensures that every visible element corresponds to verified static analysis evidence.
