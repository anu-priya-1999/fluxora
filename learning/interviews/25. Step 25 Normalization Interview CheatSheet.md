# 25. Step 25 Normalization Interview CheatSheet

## Q1: Why is a Normalization pass necessary between feature detectors and graph construction in Fluxora?
**Answer:** Feature detectors (Steps 18–24) extract raw, per-file syntactic elements (e.g. symbols, imports, re-exports, routes, ORM queries). In modern JavaScript/TypeScript, code is heavily structured using barrel files and re-exports (`index.ts`, `export * from "./foo"`, `export { x as y }`). If we constructed the graph directly from raw detector output, edges would connect to transient re-export statements rather than true code declarations, causing graph fragmentation. The Normalizer resolves re-export chains, deduplicates symbols, generates stable IDs, and links cross-detector entities deterministically prior to graph persistence (Phase 4).

## Q2: How does Fluxora handle barrel files and re-export chains without executing code?
**Answer:** The normalizer performs pure static traversal over the extracted module graph (`RepositoryModuleGraph` from Step 20). For a given re-exported symbol `(file, exportName)`, it follows `named_re_export` and `star_re_export` edges recursively until it locates the canonical `RepositorySymbol` declaration in the target file.

## Q3: How does the normalizer handle cyclic barrel dependencies (e.g., `a.ts -> b.ts -> a.ts`)?
**Answer:** The resolution engine tracks a `visited` set of `"${file}:${exportName}"` tuples. If a tuple is re-encountered during recursive traversal, the resolution halts deterministically, returns status `"cyclic"`, increments the `cycleCount` metric, and records an explicit `NormalizedUnresolvedReference` with category `"export"` rather than crashing or entering an infinite loop.

## Q4: How does symbol deduplication work, and why don't symbols with the same name get merged?
**Answer:** Canonical symbol IDs are derived from the declaration site: `sym:${relativePath}#${kind}:${parentName ? parentName + "." : ""}${name}:${offset}`. Two functions named `createUser` in `users.ts` and `orders.ts` have different relative paths and thus produce distinct canonical IDs. Deduplication occurs when barrel files re-export `createUser`; the re-exports map back to the single canonical declaration in `users.ts`, registering re-export aliases on the canonical symbol rather than duplicating the symbol.

## Q5: How is determinism guaranteed across analysis runs?
**Answer:**
1. No random UUIDs, timestamps, or process-specific state are used.
2. Canonical IDs are computed deterministically from static code coordinates.
3. Output arrays (`symbols`, `exportResolutions`, `moduleEdges`, `routes`, `events`, `databaseReferences`, `unresolved`, `diagnostics`) are explicitly sorted using deterministic string/numeric comparison keys.
4. Input structures are treated as immutable and never mutated in place.
